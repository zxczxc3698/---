# 인강 자동 편집기

특수부대 준비 강의 원본 하나를 넣으면, 무음을 걷어내고 자막을 달아
인터넷 강의 형태로 뽑아 준다.

```
python3 edit_lecture.py all 강의원본.mp4 --title "특수부대 합격 로드맵" --subtitle "1강 · 체력검정"
```

결과는 `out/` 에 쌓인다.

| 파일 | 쓸모 |
| --- | --- |
| `01_cut.mp4` | 무음만 걷어낸 중간본. 자막 없음. |
| `subs.srt` | 자막 원본. **여기서 오타를 고친다.** 유튜브에 따로 올려도 된다. |
| `final.mp4` | 제목 카드 + 자막 + 소제목까지 입힌 최종본. |
| `youtube_chapters.txt` | 유튜브 설명란에 그대로 붙이는 챕터 목록. |
| `cuts.json` | 어느 구간을 남겼는지. 챕터 시각을 맞추는 데 쓴다. |

## 준비

ffmpeg 하나면 컷과 렌더가 돌아간다. 받아쓰기만 파이썬 패키지가 더 필요하다.

```bash
# ffmpeg
brew install ffmpeg                 # macOS
winget install Gyan.FFmpeg          # Windows
sudo apt install ffmpeg             # Ubuntu

# 받아쓰기 엔진
pip install faster-whisper
```

## 세 단계로 나눠 쓰기

받아쓰기는 어떤 모델이든 전문 용어를 틀린다. **자막을 손으로 고친 뒤에 렌더하는 것이
이 도구를 제대로 쓰는 길이다.** 그래서 단계를 나눠 놓았다.

```bash
python3 edit_lecture.py cut 강의원본.mp4        # 1. 무음 걷어내기
python3 edit_lecture.py sub out/01_cut.mp4      # 2. 받아쓰기 → out/subs.srt

#    여기서 out/subs.srt 를 열어 용어·오타를 고친다 (메모장으로 충분)

python3 edit_lecture.py render out/01_cut.mp4 out/subs.srt \
    --title "특수부대 합격 로드맵" --subtitle "1강 · 체력검정"   # 3. 자막 입혀 완성
```

`all` 은 이 셋을 한 번에 돌린다. 자막 손질 없이 초벌을 볼 때 쓴다.

## 손볼 만한 값

| 옵션 | 기본 | 언제 건드리나 |
| --- | --- | --- |
| `--mode` | sound | `speech` 로 주면 사람 목소리만 남긴다. 발소리·판서 소리가 많은 촬영본에 쓴다. |
| `--db` | auto | 녹음을 재서 알아서 잡는다. 손으로 주려면 -45 처럼. `--mode speech` 에서는 쓰지 않는다. |
| `--minlen` | 0.6 | 짧은 뜸까지 걷어내려면 0.4. 말맛을 살리려면 1.0. |
| `--pad` | 0.12 | 말꼬리가 뭉텅 잘리면 0.25까지 올린다. |
| `--model` | medium | 정확도를 더 원하면 `large-v3` (느리고 메모리를 많이 쓴다). |
| `--max-chars` | 20 | 자막 한 줄 글자수. 세로 영상이면 14 정도. |
| `--denoise` | off | `light`/`strong` 으로 배경 잡음을 누른다. 렌더에만 걸려 받아쓰기엔 영향이 없다. |
| `--sub-size` | 0.044 | 자막 크기(화면 높이 대비). 1080p 에서 47px. |
| `--font` | 자동 | 맥 `AppleSDGothicNeo-Bold`, 윈도우 `Malgun Gothic`. |
| `--title` | 없음 | 주면 앞에 제목 카드를 3초 붙인다. 없으면 생략한다. |
| `--chapters` | chapters.txt | 소제목 목록 파일. 없으면 소제목을 넣지 않는다. |
| `--chapter-seconds` | 4 | 소제목이 화면에 떠 있는 시간. |
| `--no-chapter-numbers` | 꺼짐 | 소제목 앞의 `1.` `2.` 번호를 뺀다. |
| `--scale` | 없음 | `--scale 720` 처럼 주면 세로 해상도를 줄여 뽑는다. 파일을 주고받을 때. |
| `--crf` | 20 | 18이면 고화질·큰 용량, 23이면 가벼움. |
| `--terms` | terms.txt | 전문 용어 목록. 받아쓰기 정확도를 끌어올린다. |

## 챕터 / 소제목

`chapters.txt` 에 한 줄씩 적는다.

```
00:00 체력검정 기준 잡기
04:30 윗몸일으키기 자세와 반동
11:20 팔굽혀펴기 카운트 기준
```

**시각은 편집 전 원본 기준으로 적으면 된다.** 무음을 걷어내면 시간이 앞으로
당겨지는데, `cuts.json` 을 보고 알아서 맞춰 준다. 잘려 나간 무음 한가운데를
적었다면 바로 다음 말이 시작하는 자리로 당긴다.

렌더하면 두 가지가 나온다.

- 영상 왼쪽 위에 소제목이 4초간 떴다 사라진다.
- `out/youtube_chapters.txt` — 유튜브 설명란에 붙이면 재생바가 챕터로 나뉜다.
  제목 카드 길이까지 더해서 계산하고, 유튜브 규칙대로 첫 줄을 `00:00` 으로 맞춘다.

## 두 가지 자르는 방식

| | `--mode sound` (기본) | `--mode speech` |
| --- | --- | --- |
| 기준 | 조용한가 | 사람 목소리인가 |
| 남는 것 | 말소리 + 발소리·판서 소리 | 말소리만 |
| 맞는 데 | 앉아서 말만 하는 강의 | 움직이며 찍은 촬영본, 준비 장면이 섞인 원본 |
| 필요한 것 | ffmpeg (numpy 있으면 더 정확) | faster-whisper |

말하는 사이사이 숨 고르는 맛을 남기려면 `sound`, 말만 촘촘히 뽑아내려면 `speech` 다.

## 여러 개를 한 번에

40개를 손으로 돌릴 수는 없다. `batch.py` 가 목록을 받아 차례로 처리한다.

```bash
python3 batch.py 목록.txt -o 결과 --mode speech --denoise light
```

목록 파일은 한 줄에 하나씩. 제목은 없어도 된다.

```
https://drive.google.com/file/d/<아이디>/view | 1강 체력검정 기준
https://drive.google.com/file/d/<아이디>/view | 2강 윗몸일으키기
```

폴더째로 넘겨도 된다. 안에 든 영상을 찾아 `결과/_목록.txt` 로 적어 두고 차례로 돌린다.

```bash
python3 batch.py --folder "https://drive.google.com/drive/folders/<아이디>" -o 결과
```

폴더 읽기는 구글 페이지 짜임새에 기대고 있어서 언젠가 깨질 수 있다.
안 되면 목록 파일을 쓰면 된다.

드라이브 링크면 알아서 받아 온다. 「링크가 있는 모든 사용자」로 열어 두어야 한다.
로컬 파일 경로나 다른 직접 링크도 그대로 쓴다.

- 중간에 끊겨도 다시 돌리면 **끝난 것은 건너뛰고 이어서** 한다 (`결과/_진행.json`).
- 편집이 끝난 원본은 지운다. 40개를 받아 두면 디스크가 모자란다. 남기려면 `--keep-source`.
- 강의별 챕터는 `--chapter-dir 폴더` 로 주고, 그 안에 `01.txt`, `02.txt` 로 둔다.
- 실패한 것은 마지막에 까닭과 함께 모아 보여 준다.

## 소리가 작게 녹음됐을 때

핀 마이크가 안 잡혀서 방 건너편 소리로 녹음되는 일이 흔하다. 그런 원본은

- `--db auto` 가 알아서 낮은 임계값을 잡으므로 컷은 문제없다.
- 소리를 키우면 방 웅웅거리는 소리도 같이 커진다. `--denoise light` 로 눌러 준다.
- 받아쓰기는 소리를 키운 뒤에 돌린다. 잡음 제거는 최종 렌더에만 걸어서,
  말까지 갉아먹어 받아쓰기를 망치는 일이 없게 해 두었다.

근본 해결은 촬영 쪽이다. 핀 마이크가 실제로 녹음되고 있는지 먼저 확인하는 게 낫다.

## 얼마나 걸리나 (4코어 CPU 기준 실측)

5.5분짜리 결과물을 뽑을 때:

| 렌더 설정 | 걸린 시간 | 용량 |
| --- | --- | --- |
| 1080p `--preset medium` | 279초 | 166MB |
| 1080p `--preset veryfast` | 125초 | 161MB |
| 720p `--preset veryfast --scale 720` | 74초 | 69MB |

1080p 에서 고화질 설정은 시간만 두 배 쓰고 용량은 거의 같다. 판서 앞에서
말하는 화면은 어느 쪽으로 눌러도 비슷하게 압축되기 때문이다. **720p 로 뽑는 게
거의 언제나 맞다.** 인강 글씨는 720p 로 충분히 읽힌다.

받아쓰기가 제일 오래 걸린다. medium 모델이 말하는 시간의 1.25배쯤 쓴다
(말이 빽빽한 5분 음원에 6.1분). 무음을 걷어낸 뒤에 돌리므로, 원본 길이가 아니라
**실제 말하는 길이**가 시간을 정한다.

10분짜리 강의 한 편에 대략 18분 안팎, 40편이면 12시간 남짓이다.

## 파일이 너무 클 때

`--scale 720 --crf 26` 으로 뽑는다. 말하는 사람이 크게 움직이지 않는
강의 영상은 이 정도로도 글씨가 충분히 읽히고, 용량은 몇 분의 일로 준다.
챕터별로 나눠 올리고 싶으면 `chapters.txt` 의 시각을 보고 잘라 쓰면 된다.

## 용어집

`terms.txt` 에 강의에서 쓰는 말을 적어 두면 받아쓰기 전에 모델에게 귀띔한다.
707특임단, 천리행군, IBS 같은 말은 적어 두지 않으면 거의 틀린다.

## 하는 일의 순서

1. 0.025초 칸마다 음량을 재서 바닥 잡음과 말소리 사이에 임계값을 놓고, 남길 구간만
   `select` 표현식으로 한 번에 이어 붙인다. 토막이 몇백 개여도 인코딩은 한 번만 한다.
   `--mode speech` 면 음량 대신 목소리인지를 보고 고른다.
2. 소리 크기를 방송 기준(-16 LUFS)으로 고른다. 강의마다 목소리 크기가 들쭉날쭉한 걸 잡아 준다.
3. 낱말 단위 타임스탬프로 받아쓰고, 문장 끝과 쉬는 자리에서 끊어 자막 한 장씩 만든다.
   한 줄 20자, 두 줄, 최대 6초, 최소 1.1초를 지킨다.
4. 흰 글자에 검은 테두리로 자막을 태우고, 소제목은 왼쪽 위 반투명 띠로 얹고,
   앞에 제목 카드를 붙인다.

## 하지 않는 일

- 화면 전환 효과, 배경음악, 줌인 같은 연출은 넣지 않는다.
- 말실수나 군더더기 문장은 지우지 않는다. 무음만 판단한다.
- 판서·슬라이드 화면을 따로 잡아내지 않는다.
- 챕터 구간을 스스로 나누지 않는다. `chapters.txt` 에 적어 준 대로만 얹는다.
