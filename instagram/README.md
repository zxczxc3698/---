# 인스타그램 릴스 분석

릴스 지표를 Instagram Graph API 로 직접 받아 대시보드와 분석 보고서를 만든다.
외부 서비스도, 유료 크레딧도, `pip install` 도 필요 없다.

세팅은 **[SETUP.md](SETUP.md)** 를 따른다. 처음 한 번 30분쯤 걸리고, 그 뒤로는 명령 두 줄이다.

```sh
cd instagram
python3 collect.py --limit 30     # 지표 수집
python3 build_dashboard.py        # 대시보드 생성
```

## 구성

| 조각 | 하는 일 |
| --- | --- |
| `collect.py` | Graph API 에서 릴스·인사이트·계정 스냅샷을 받아 `data/` 에 쌓는다 |
| `build_dashboard.py` | 쌓인 데이터를 계산해 `dashboard.html` 을 만든다 |
| `template.html` | 대시보드 화면의 원본. 데이터는 빌드할 때 주입된다 |
| `report/OUTLINE.md` | 종합 분석 보고서를 무엇을 근거로 쓸지 정해 둔 얼개 |
| `competitors.example.json` | 경쟁 계정 비교용 서식 |
| `SETUP.md` | 토큰 발급부터 자동 수집까지 |

## 이 대시보드가 보는 방식

**조회수를 성적표로 쓰지 않는다.** 조회수는 추천이 얼마나 밀어줬는지의 결과다.
콘텐츠가 좋았는지는 `저장 ÷ 조회`, `공유 ÷ 조회` 가 말해 준다. 조회수가 큰 영상은
저장·공유의 절대 수도 따라서 커지므로, 비율로 환산해야 진짜 잘 된 영상이 보인다.
화면의 정렬과 순위는 모두 비율 기준이다.

**게시 7일이 안 된 릴스는 순위에서 뺀다.** 수치가 아직 자라는 중이라 최근 것이
불리하게 잡힌다. 카드에 `집계중` 으로 표시하고 비교에서 제외한다.

**표본 2편 미만인 묶음은 세지 않는다.** 요일별·시간대별·해시태그별 통계에서
1편짜리 묶음은 우연과 구별되지 않는다.

**없는 값은 채우지 않는다.** API 가 주지 않은 지표는 0 이 아니라 `N/A` 로 남는다.
0 은 "없다"가 아니라 "0이다"로 읽히기 때문이다.

## 한계

- **경쟁 계정 비교는 자료를 직접 넣어야 한다.** API 는 내 계정만 준다.
  남의 계정은 저장·공유가 공개되지 않으므로, 밖에서 셀 수 있는 팔로워·조회·좋아요·댓글로만 견준다.
- **계정 단위 일별 지표는 수집을 시작한 날부터 쌓인다.** 과거 소급은 API 가 주는 범위까지만이고,
  팔로워 수 이력은 아예 소급되지 않는다. 빨리 돌리기 시작할수록 추이가 길어진다.
- **토큰은 60일마다 갱신해야 한다.** `python3 collect.py --refresh-token`.
- 프로페셔널 계정으로 전환하기 전에 올린 게시물은 인사이트가 없다.
